# VK-08 — World phase B on Vulkan (water, wind, transparent meshes): how to test

Windows with a Vulkan driver, a branch that contains REN-35 (round 34) and VK-08 (`agents/vulkan`).
Commands run from the repository root in `cmd`.

## What changed

- **Depth copy.** `RhiCommandList.blit` with `BlitMask.DEPTH`/`COLOR_DEPTH` now copies the depth attachment on
  Vulkan (`VkCommandList.copyDepth`, `vkCmdCopyImage`; region math in `VkOrientation.depthCopyRegion`). The water
  pass's scene copy (`SceneDepthCopy`) used to stay empty there. `vkCmdCopyImage` is used instead of a blit because
  blitting depth formats is optional in Vulkan; the RHI already requires equal sizes and NEAREST for depth.
- **Fragment output locations in `#ifdef` branches.** `GlslToVulkan` numbered `out` declarations straight through
  the source, so `water.glsl` (`out vec3 color` under `#ifdef PICKING`, `out vec4 color` under `#else`) put the real
  colour output on location 1. No attachment there, so every water fragment was dropped. Each `#else`/`#elif` branch
  now numbers its fragment outputs from the same start, and a varying declared again in another branch keeps its
  first location.

## Steps

1. **Opt in.** `set SKATE_RHI=vulkan`. Until the LunarG SDK is installed, also `set SKATE_VK_VALIDATION=0` (VK-07).
2. **Run the parity test.**
   `gradlew.bat :test --tests com.pafoid.skate.engine.render.rhi.vulkan.VulkanWorldPhaseBParityGpuTest` -> PASSED
   (about 25 s). It renders 6 views with OpenGL, then with Vulkan, with the Geometry, Shadow, Water and Transparent
   passes.
3. **Read the report.** In `build\vk08\report.txt`, no line has `FAIL`. Results on the reference machine
   (2026-11-17):

   | View | Mean diff (/255) | Within 2/255 |
   |---|---|---|
   | main-pool-ssr-off | 0.013 | 100.000% |
   | main-pool-ssr-medium (16 steps) | 0.013 | 100.000% |
   | main-pool-ssr-high (32 steps) | 0.013 | 100.000% |
   | main-pool-storm (wind 16 m/s, wind-driven waves) | 0.011 | 99.998% |
   | showcase-transparent-over-water | 0.000 | 100.000% |
   | showcase-materials-transparent | 0.000 | 100.000% |

   Water tolerance: mean ≤ 0.5/255 and 99.5% of pixels within 3/255. SSR and refraction re-sample the scene copy at
   normal-dependent offsets, so a rounding difference can move one sample by a texel along silhouettes (max 81 on a
   handful of pixels in the storm view). Other views use the VK-03 tolerance.
4. **Look at the frames.** `main-pool-storm-vulkan.png` shows the pool with storm waves, foam and the refracted
   skater; `showcase-transparent-over-water-vulkan.png` shows the blue blended cube half under a pool, drawn over the
   water surface. The `*-diff.png` images are black.
5. **Shader coverage without a GPU.** `gradlew.bat :test --tests "com.pafoid.skate.engine.render.rhi.vulkan.EngineShadersVulkanTest"`
   compiles every engine shader plus the WIND variants (mesh, skinned mesh, shadow, alpha-tested shadow, picking) and
   the water PICKING variant to SPIR-V, and checks each colour output sits on location 0.
6. **Check OpenGL is unchanged.** Nothing outside `render/rhi/vulkan/` changed. Unset `SKATE_RHI` and run
   `WaterGpuTest`: it still passes.

## Not covered here

- The renderer does not draw meshes with the WIND variants yet (vegetation, REN-29 task 14b). Wind reaches the water
  shader (detail normals, wind-driven waves), and the mesh WIND variants are compile-checked only.
- Zero validation messages stays unproven until VK-07 (LunarG SDK).
