# EDT-60 phase 0 manual test steps: persistent object ids

Scene files now give each object a persistent `guid` instead of the session `uId`, and no longer store `isDirty`. Saving an unchanged scene writes the same bytes. Old scenes are not migrated: their objects get new ids on the first save, and old joints connected to another body fall back to a world anchor.

1. Run `.\gradlew.bat run` and create a new project. Open `Scenes\MainScene.scene` in a text editor. Expected: each object has a `"guid"` of 32 hex characters; there is no `"uId"` and no `"isDirty"`.
2. Copy `MainScene.scene` somewhere else. In the editor, open MainScene and save it without changing anything (**File > Save Scene**). Compare the two files (`fc /b old.scene Scenes\MainScene.scene`). Expected: no differences.
3. Close and restart the editor, open the project, and save MainScene again without changes. Compare again. Expected: still identical. Repeat steps 2–3 with the FeatureShowcase scene.
4. Move an object, then save. Expected: the diff shows only that object's transform lines.
5. Select an object that has children (for example **HUD**), copy and paste it, then save. Expected: the pasted object and its children each have new guids; no guid appears twice in the file.
6. In the FeatureShowcase scene, select **[Joints] HingePendulum** and set its Joint's **Connected Body** to another physics object. Save, restart the editor, and reopen the scene. Expected: the joint still shows that body, and in Play the two bodies stay connected.
7. Edit something (the tab shows the unsaved marker), press **Play**, then **Stop**. Expected: the unsaved marker is still there and the expanded nodes in the Hierarchy are unchanged.
8. Save, reopen the scene, and check the tab. Expected: no unsaved marker right after opening.
