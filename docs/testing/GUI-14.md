# GUI-14 — Esc in the exported game: how to test

**Bug:** in an exported game, pressing Esc closed the game instead of opening the pause menu.

**Cause:** `KeyListener` (and `MouseListener`) asked ImGui whether it was capturing the keyboard
(`ImGui.getIO().wantCaptureKeyboard`) every time a key was down. Only the editor creates an ImGui context. In the
exported game, that call ends the JVM process at once: no exception the game can catch, no crash log, the window
just disappears. Esc is the first key most players press (`ui.cancel` → pause menu), so the game "closed on Esc".
A mouse click hit the same call through `isMouseButtonDown`. `glfwSetWindowShouldClose` was not involved: only the
pause menu's Quit button and the editor's Exit call it.

**Fix:** the engine no longer imports ImGui. `KeyListener.captureKeyboard` and `MouseListener.captureMouse` are hooks
that default to "not captured". The editor's `ImGuiLayer` installs the ImGui versions right after it creates its
context, so the editor behaves as before.

## Automated

`gradlew.bat :test --tests com.pafoid.skate.engine.ui.EscapePauseKeyPathTest` → 4 tests pass:
- Esc goes through the real key path (GLFW key callback → `KeyListener` → `ActionInputReader` `ui.cancel` →
  `UiInputSystem` → `PauseMenuSystem`) with no ImGui context. It opens the pause menu and freezes the game, Esc again
  resumes, and Quit is never called.
- Keys and mouse clicks are read without an ImGui context.
- The editor's capture hooks still hide input from the game.
- No file under `engine/` imports `imgui`.

Without the fix, this test class does not fail normally: the test JVM process ends inside `ImGui.getIO()`.

## Manual (exported game)

1. `gradlew.bat run`, open a project with a playable scene (for example the Feature Showcase sample), then
   **File → Export** to a folder.
2. Start the exported game from that folder (`skate-game.jar` next to `game.bin`).
3. Press **Esc**: the pause menu appears and the game freezes. Press **Esc** again: the menu closes and the game
   resumes. Open it again and click **Resume**: same result.
4. Click with the mouse in the game, and press gameplay keys: the game keeps running.
5. Open the menu and click **Quit**: only now does the game close.
6. In the editor, check that typing in an ImGui text field (for example the console filter) does not move the
   player during Play, and that clicks on editor panels do not reach the game view.

Note: a project generated by `skate sample` (CLI) stores absolute asset paths (`defaultScene` and the asset
references in its scenes). Its CLI export cannot load them in the game. Export from the editor, or fix those paths
first.
