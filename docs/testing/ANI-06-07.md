# ANI-06 / ANI-07 manual test steps

Covers the work committed as **ANI-06** (animation events published on the `EventSystem`) and **ANI-07** (serializable blend trees, controller editing API, JSON).

These two tasks are engine APIs. **They have no editor UI and no gameplay subscriber yet** (see "Not testable yet"), so a person cannot see an event or a blend tree in the editor. What a human can verify is (A) the automated tests, (B) that the CLI project tooling still works, and (C) that the editor still starts, plays a scene and renders a skinned character after the changes.

Run every command from the repository root (`skate-worktrees/animation`), in Windows `cmd`/PowerShell. From WSL, prefix with `cmd.exe /c`. Natives are Windows-only, so always use `gradlew.bat`.

## A. Automated tests (verified when this document was written)

1. Run the ANI-07 tests and the ANI-06 marker test:

   ```
   .\gradlew.bat :test --tests "*ControllerEditingTest" --tests "*AnimationGraphTest.StateMachine_FiresEventsOncePerCrossing_AndAcrossLoops"
   ```

   Expected: `BUILD SUCCESSFUL` and these 10 lines ending in `PASSED`:
   - `AnimationGraphTest > StateMachine_FiresEventsOncePerCrossing_AndAcrossLoops()` — a marker at 0.5 fires once per crossing and again on the next loop; the fired event now carries the state name (`FiredEvent("push", "footstep")`).
   - `ControllerEditingTest > Json_RoundTripsBlendTreesAndStates()` — `toJson()` then `fromJson()` gives an equal asset, and the JSON contains `blend1d`.
   - `ControllerEditingTest > Motions_BuildBlendTreeFromDefAndResolveStateMotionKey()` — a blend tree defined in the asset at `speed = 0.5` between clips at 0 and 10 evaluates to 5.
   - `ControllerEditingTest > Motions_UnknownClipFailsToBuild_AndIsReportedByIssues()` — a missing clip throws on build and is listed by `issues()`.
   - `ControllerEditingTest > Issues_ReportsUnknownStateMotionAndEventTimeOutOfRange()`
   - `ControllerEditingTest > BlendEditing_AddMoveAndRemoveChildren()` — add child, change threshold, remove child; removing every child is refused.
   - `ControllerEditingTest > Blend2D_EditingChangesPositions()`
   - `ControllerEditingTest > Editor_RenameUpdatesTransitionsAndDefault()`
   - `ControllerEditingTest > Editor_RemoveStateDropsTransitions_AndFailedEditsLeaveAssetUnchanged()` — a failed edit leaves the asset unchanged (the basis for editor undo snapshots).
   - `ControllerEditingTest > Editor_TransitionPriorityAndEventsStaySorted()`

2. Run the whole root-project suite:

   ```
   .\gradlew.bat :test
   ```

   Expected: `BUILD SUCCESSFUL`. Stack traces such as `java.lang.IllegalStateException: gl gone` and `java.lang.RuntimeException: Test exception` in the output are deliberate (tests that check error logging) and are not failures. Use the `:` prefix; without it the `tools:cli` subproject fails on the test filter.

   Expected: `BUILD SUCCESSFUL`, and a line `Generated sample project at ...\build\manual-test\FeatureShowcase\FeatureShowcase.skateproject`. A log line `Could not add component DirectionalLightComponent ... Sun gameObject` is printed during generation in my run; I did not investigate it and it did not stop the build.

If it works on your machine (a GL-capable session), expected output is the engine stats and exit code 0.

3. Validate the generated project:

   ```
   .\gradlew.bat :tools:cli:run --args="validate build\manual-test\FeatureShowcase"
   ```

   Expected: `Project is valid (6 scenes)`.

## C. Editor smoke test (NOT run by me; I have no display)

Goal: confirm skinning (ANI-05 UBO), IK and controller changes did not break rendering or playback.

1. Launch the editor: `.\gradlew.bat run`. Expected: the editor window opens (project wizard or project switcher on a clean state).
2. Create a new project: in the wizard (`Project Wizard`, "Welcome to SkateSim Engine") type a name in *Project Name*, set *Location* to an existing writable folder (the wizard shows "Valid location"), then click *Create Project*. If the wizard is not shown, use the menu **File > New Project**. Expected: an empty project opens with a default scene.
   - Alternative using the sample from section B: open `build\manual-test\FeatureShowcase\FeatureShowcase.skateproject` from the project switcher (*Select a recent project or create a new one*) and open scene `Animation`.
3. Scene `Animation` (sample) shows the bundled character with an Animator. Expected: the character renders in bind pose without stretched triangles or a collapsed mesh. If it appears flat or exploded, report it: that points at the skinning uniform-block shader change (ANI-05).
4. Press Play in the viewport toolbar. Expected: no crash, no GL error spam in the log, the character stays rendered.
5. In the Inspector, select the character's `Animator`, assign a clip from `EngineDefaults/Characters/animations`, press the Animator's *Play* button. Expected: the character animates smoothly.

## Not testable yet

- **Receiving `AnimationEvent`.** `AnimationSystem` publishes `AnimationEvent(gameObject, name, state)` through the `EventSystem` whenever a controller state's marker is crossed. Nothing in the repository subscribes to it, and there is no editor UI to define markers or to attach a controller to an `Animator`. A subscriber in gameplay code (footsteps, trick landings) is needed before this can be seen. The marker timing is covered by test A.1; the publish call itself has no automated test (it needs a running scene).
- **Editing blend trees.** `ControllerEditor`, `MotionDef` and `AnimationControllerAsset.toJson()/fromJson()` have no editor window or file loader yet. They are covered only by the unit tests in A.1.
