# QA-15: CI green — failure causes and evidence

GitHub Actions (`.github/workflows/ci.yml`, `windows-latest`) failed on all 75 runs listed by `gh run list --limit 200` (Oct 27 – Nov 5, 2026; 4 more were cancelled), master included. Failed tests were read from the job logs (`gh api repos/{owner}/{repo}/actions/jobs/<id>/logs`) and the `reports` artifacts (`gh run download <run> -n reports`) of 13 runs.

| Failing test(s) | Runs | Root cause | Fix |
|---|---|---|---|
| `ShaderValidationTest > initializationError` | every run (Oct 27 – Nov 5) | `IllegalStateException: Failed to create the GLFW window`: the runner has no GPU, so there is no OpenGL context. The test also scanned `assets/shaders`, which does not exist, so even locally it validated **zero** shaders. | New `@GpuTest` (`src/test/.../testing/GpuTest.kt`) = `@Tag("gpu")` + `@DisabledIfEnvironmentVariable(CI=true)` with a reason. Applied to `ShaderValidationTest` and `UiBatchRendererGlTest`. The shader test now compiles every full shader in `src/main/resources/shaders` from the classpath (16 locally), skips include-only files, and fails if it finds fewer than 10. |
| `ProjectExporterTest` (1 test from Oct 30, then 3) | Oct 30 – Nov 5 | **Real bug** in `AssetsPacker.pack`: it relativized canonical files against a non-canonical project folder. The runner's temp folder is the 8.3 short path `C:\Users\RUNNER~1\…`, which canonicalizes to `C:\Users\runneradmin\…`, so every pack entry became `../../../../runneradmin/…/Textures/used.png`. A user whose project path has a short name, a junction or a `..` gets the same broken `game.bin`. | Both sides canonical in `AssetsPacker.pack`. The project folder itself is no longer treated as hidden when its path ends in `..`. Regression test: `ProjectExporterTest.Export_NonCanonicalProjectPath_PacksProjectRelativePaths` (fails without the fix). |
| `MaterialExportTest` x3 (Nov 4–5), later `ExportedReferencesTest` x2 (AST-09 merged the first into the second) | Nov 4 – Nov 5 | Same bug (`FileNotFoundException: C:\Users\RUNNER~1\…\rock.skmat`; manifest paths `../../runneradmin/…`). | Same fix. |

The game jar (AST-11) is **not** a cause: every export test injects a fake jar (`GameJarSearch`) or uses `ExportTarget.PACK_ONLY`, and the clean-clone run below has no `build/libs`.

## Local reproduction of CI conditions

- **8.3 short temp path:** `set TMP=C:\workspace\SKATE-~1&& set TEMP=C:\workspace\SKATE-~1&& gradlew.bat --no-daemon :test --rerun --tests …ProjectExporterTest --tests …ExportedReferencesTest`. Before the fix this gives the same 5 failures as CI, with the same `../../` manifest paths. After the fix, all pass.
- **No GL:** `set CI=true&& gradlew.bat --no-daemon :test --rerun --tests …ShaderValidationTest --tests …UiBatchRendererGlTest`. All 4 are SKIPPED with the reason, and `@BeforeAll` doesn't run. Without `CI`, all pass on a GPU machine.
- **Full CI command on a clean clone:** `git clone` of `agents/qa` (no `build/`, no game jar) mapped to its own drive with `subst Q:`, like the runner's `D:\a\skate\skate` versus `C:` temp, plus the short `TMP` and `CI=true`, then `gradlew.bat --no-daemon build test jacocoTestReport --console=plain`. Result: `BUILD SUCCESSFUL in 2m 4s`, 1629 tests passed, and only the 4 `@GpuTest` tests skipped. That includes the `tools:cli` and `tools:mcp` builds, `jacocoTestReport`, and the export tests without a built game jar.

Note: Gradle doesn't treat `CI` or `TMP` as test inputs, so use `--rerun` (or `--rerun-tasks`) when switching them, or the test task stays UP-TO-DATE.

## Not reproducible locally

- The hosted runner image itself (Windows Server, its JDK build, no display adapter). The "no GPU" behaviour is covered by `CI=true` skipping, not by running without a GPU. Whether GLFW could create a software context there is irrelevant now.
- GitHub's own `CI=true` and checkout path. They were simulated with an explicit `CI=true` and `subst`.
- The lead should confirm on the next PR's CI run. The workflow now also uploads `build/test-results/test` (JUnit XML) for faster triage.
