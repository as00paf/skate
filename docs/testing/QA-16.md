# QA-16 — Vulkan parity suite and exported Vulkan game: how to run

Windows, a GPU with a Vulkan driver. Commands run from the repository root in `cmd`. Both GPU tests are `@GpuTest`: they are skipped on CI (`CI=true`, no GPU) and when `SKATE_RHI` is not `vulkan`.

1. **Opt in, without the validation layer.** Run `set SKATE_RHI=vulkan` and `set SKATE_VK_VALIDATION=0`. Do **not** set `VK_ADD_LAYER_PATH` or `VK_INSTANCE_LAYERS` to the downloaded nightly layer. Once the LunarG SDK is installed, use `SKATE_VK_VALIDATION=1`: any validation error then fails both tests.
2. **Full-frame parity suite.** Run `gradlew.bat --no-daemon :test --rerun --tests com.pafoid.skate.engine.render.rhi.vulkan.FeatureShowcaseVulkanParityGpuTest`. It takes about 25 s, and both tests pass.
   - It renders 16 views with every render pass on (shadows, geometry, particles, UI, post-processing), first with OpenGL, then with Vulkan.
   - The views: MainScene (scene, skater, every post effect at once), the showcase UI overview, and one view per showcase area (lights, shadows, materials, particles, physics with collider wireframes, joints, vehicle, audio, prefabs, netcode, animation, fog).
3. **Read the report.** In `build\qa16\report.txt`, no line ends in `FAIL`. Tolerances are the VK tasks' own:
   - VK-03: mean ≤ 0.25 and 99.9% of pixels within 2/255. This applies to every view not listed below.
   - VK-06 debug lines: 99.8% within 2/255, for `showcase-physics`.
   - VK-05 SSAO: 99% within 16/255, for `main-post-all`.
   - First local run (Nov 6): every view at a mean of 0.045 or less; the showcase areas at 0.000 or 0.004.
4. **Look at the frames.** In `build\qa16`, compare `<view>-gl.png` with `<view>-vulkan.png`. Each `*-diff.png` is black apart from scattered pixels. `showcase-particles-vulkan.png` shows fire, smoke and the fountain under the legend panel and widgets.
5. **Exported Vulkan game.** Run `gradlew.bat --no-daemon :test --rerun --tests com.pafoid.skate.editor.systems.ProjectLifecycleEndToEndTest`. All 10 steps pass, and the output prints `QA-16: exported game requested VULKAN, runs on VULKAN (VulkanDevice)`.
   - Step 9 runs everywhere, CI included: a Vulkan-backend project is created, saved, reopened from Recent Projects and exported with the wizard. The packed project, `game.settings.json` and `GameGraphics.requested` all say VULKAN.
   - Step 10 starts that export like GameMain: `GameGraphics.start` opens a hidden Vulkan `Window`, the engine opens the pack and plays MainScene with every pass for 120 presented frames. The frame must not be flat, the skater's controller must load, and there must be no ERROR log.
6. **Without a Vulkan driver**, step 10 checks the documented fallback instead: the log line `Graphics backend VULKAN could not start (…); falling back to OPENGL.`, the note in `game.settings.json`, and that the game still runs on OpenGL. This machine has a driver, so that branch did not run here; `GameGraphicsTest` unit-tests the same fallback.
7. **CI-like run.** Run `set CI=true` and then `gradlew.bat --no-daemon test --rerun`. Both GPU tests show as skipped. `Parity_CoversEveryShowcaseArea` and lifecycle steps 1–9 still run.

**Adding a showcase area (GameEngine.md rule 8):** a new area gets a focus view in `FeatureShowcaseVulkanParityGpuTest` automatically. If it needs set-up before rendering (like animation, particles, physics), add its key to `special` and give it its own view. `Parity_CoversEveryShowcaseArea` runs on CI and fails if an area ends up without a view.
