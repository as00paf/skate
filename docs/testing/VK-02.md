# VK-02 test steps: Vulkan resources (memory, uploads, descriptors, samplers)

VK-02 is backend plumbing for exported Vulkan games; the editor and default projects stay on OpenGL. These steps run
the opt-in Vulkan checks on a machine with a Vulkan driver (Windows, `cmd`).

1. `.\gradlew.bat run`, create a NEW project, open `FeatureShowcase` and press Play → everything renders as before
   (OpenGL is unchanged).
2. `set SKATE_RHI=vulkan`, then
   `.\gradlew.bat :test --tests com.pafoid.skate.engine.render.rhi.vulkan.VulkanResourcesGpuTest` → 8 tests pass:
   textures (mips, 2D arrays, cube maps, RGB8, depth with compare samplers) read back intact, shared samplers,
   every buffer kind including dynamic versions, render targets, the default program and no leaked allocations.
3. Same shell: `.\gradlew.bat :test --tests com.pafoid.skate.engine.render.rhi.vulkan.VulkanGeometryPassGpuTest` → both
   tests pass; `build/ren13/report.txt` shows the geometry pass within 1/255 of OpenGL and `build/ren13/all-passes.txt`
   shows MainScene and FeatureShowcase rendered with every pass but post-processing (about 98% of pixels within 8/255).
4. With a Vulkan validation layer available (Vulkan SDK, or the Khronos layer folder in `VK_ADD_LAYER_PATH`), add
   `set SKATE_VK_VALIDATION=1` and rerun steps 2-3 → no `skate.rhi.vulkan` validation messages in the test output.
5. `set SKATE_RHI=` and rerun step 2 → the GPU tests are skipped (opt-in).
