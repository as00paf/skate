# VK-06 — Runtime UI, particles and debug lines on Vulkan: report

Status: done (validation-layer run pending the LunarG SDK). Owner: skate-gameui (rule 1 exception). Depends on VK-05's
orientation convention (`agents/vulkan` 464a8839): offscreen targets render unflipped, in GL row order.

## Result

`UiPass`, `ParticlePass` and `DebugPass` were already written against the RHI (buffers, pipeline states, scissor,
instanced draws), so **no pass or backend change was needed** for parity. VK-06 adds the proof and removes per-frame
allocations from the UI path.

`VulkanOverlayParityGpuTest` renders the FeatureShowcase with the geometry pass plus the pass under test, on each
backend (1280x720). Particles are seeded and stepped identically, and no Play-time systems run.

**Tolerance**: as VK-03 (mean ≤ 0.25/255, ≥ 99.9% of pixels within 2/255), except views with debug geometry, which
need ≥ 99.8%. The editor's X/Z axes are 100 m ribbons a few centimetres wide. When one end is behind the camera
(`debug-grid`), each driver clips them at the near plane with different rounding, and the ribbon edge shifts by a
pixel or two along its length. Seen from where the axes stay in front of the camera (`debug-grid-above`), the views
match at 99.999%. Bresenham line rasterization (`VK_EXT_line_rasterization`) and a larger depth pull for the
ribbons were both tried, and neither changed it.

Before VK-05, the UI views failed: about 1.5% of pixels on SDF glyph edges differed, and some horizontal grid lines
sat one pixel off. Both came from the flipped offscreen viewport, which changes edge tie-breaking. VK-05 removed it.

## UI path without per-frame allocation

- `UiDrawList`:
  - Batches are pooled.
  - Scissor rects are reused by push order while their value is unchanged.
  - 9-slice panels use scratch arrays.
  - Recording a frame like the previous one allocates nothing; `UiDrawListAllocationTest` measures this in a fresh JVM.
- `UiBatchRenderer`: uploads the used vertices from a reused staging buffer into a vertex buffer that only grows
  (`update`). It used to copy the vertex array and re-create the buffer storage every frame. The OpenGL frames of
  every view above are byte-identical before and after.

## Notes

- Validation-sensitive spots for the SDK run:
  - the particle instance buffer is resized when the particle count grows;
  - UI scissor rects change between draws inside one pass;
  - debug lines use `lineWidth` 4 (needs `wideLines`, else 1).
- Allocations left outside the UI path, already reported: VkCommands per draw (fixed in VK-05), and the RHI `binding()`
  / `dummyFor` pairs (skate-render).
