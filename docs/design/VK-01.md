# VK-01 — Windowed Vulkan runtime: notes

Status: done. Owner: skate-vulkan. Builds on REN-13 (`docs/design/REN-13.md`). Paths are relative to
`src/main/kotlin/com/pafoid/skate/engine/render/rhi/vulkan/`.

## What changed

| Piece | File | Notes |
|---|---|---|
| Surface, present queue, validation | `VkCore.kt` | `VkCore.create(window, validation)`: GLFW instance extensions plus `VK_KHR_swapchain`, and a queue family that does graphics and presents. Validation turns on with `-Dskate.vk.validation=true` or `SKATE_VK_VALIDATION=1`; errors and warnings are counted (`VkCore.validationErrors`). |
| Submission serials, deferred destruction | `VkFrames.kt` (`SubmissionTracker`), `VkCore.destroyLater` | Each queue submission gets a serial. `destroyLater` runs a block once every submission made so far has finished, and so has the frame still being recorded. Blocks run at fence waits, idle waits and close. `HostBuffer.close` uses it. VK-02 moves the other resources to it. |
| Frames in flight | `VkFrames.kt` (`FrameRing`), `VkFrameLoop.kt` | Two slots by default. Each slot has a fence and one primary command buffer, plus an acquire semaphore in the swapchain. A slot is reused only after its fence signals. Its transient memory (uniform ring, descriptor pools) is then reset through `VulkanDevice.onFrameSlotReady`, which is where VK-02's `VkFrameResources.beginFrame(slot)` goes. |
| Swapchain | `VkSwapchain.kt` | Format B8G8R8A8_UNORM, which writes linearly like GL's default framebuffer; gamma stays in the post shader. Vsync uses FIFO; without vsync, MAILBOX, then IMMEDIATE. The swapchain is recreated before acquire when the framebuffer size changed or presentation reported it out of date or suboptimal. While the window is minimized (0x0), no image is acquired. Each image gets its own render-finished semaphore. The choices live in `SwapchainPolicy` and are unit-tested. |
| Back buffer as the default target | `VkCommands.kt`, `VulkanDevice.kt` | `beginPass(null)` and `blit(src, null)` acquire the image lazily. The back buffer pass is colour only and ends in `PRESENT_SRC`. When no image is available (minimized), the pass is recorded as a no-op and its draws are dropped. `readPixels(null)` reads the back buffer, swizzled to RGBA. Blits convert GL bottom-left rects; both images are stored top row first, so nothing is mirrored. |

## Frame model

- A frame is **one command buffer**: all passes of the frame record into it, and `endFrame` submits it with the
  slot's fence, then presents. The first command opens a frame. `beginFrame` ends a frame that is still open, because
  `Renderer.render` calls `beginFrame` every frame and nothing calls `endFrame` yet. Without `endFrame`, presenting
  waits until the next frame's `beginFrame`.
- `readPixels` in the middle of a frame submits what was recorded, waits, and keeps recording the same frame.
- `core.oneShot` (uploads, readback) is a separate submission. It runs **before** frame commands that are recorded
  but not yet submitted.

## Follow-ups

- **GPL-19 / Window:** call `device.endFrame()` after each game frame, and create a no-API window for Vulkan games.
  The game's `testDraw` blit already presents correctly on Vulkan.
- **VK-02:** version host-visible dynamic vertex buffers per frame in flight. Until then, a buffer rewritten while an
  earlier frame is in flight, or between passes of one frame, races with the GPU. The REN-13 geometry only writes
  static buffers and uniform blocks, which are snapshotted at record time. Also: a growable uniform ring, and the
  remaining resources moved to `destroyLater`.
- Validation runs locally only. No layer is installed on CI; GPU tests are skipped there.
