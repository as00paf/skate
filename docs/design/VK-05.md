# VK-05 — Post-processing on Vulkan: orientation convention and report

Status: done (validation-layer run pending the LunarG SDK). Owner: skate-vulkan. Agreed with skate-render (VK-04
shadows) and skate-gameui (VK-06 UI, particles, debug), which rely on the same convention. Paths are relative to
`src/main/kotlin/com/pafoid/skate/engine/render/rhi/vulkan/`.

## 1. Texture orientation (Y-flip) convention

Until VK-05 every pass used a flipped (negative-height) viewport. That stored render targets top row first, while
every engine shader samples them with GL texture coordinates (v = 0 is the NDC y = -1 row). Post effects, shadow
lookups and SSAO therefore read mirrored images, and readback and blits had to undo the flip after the fact.

**The convention now (`VkOrientation.kt`):**

| Image | Stored | Viewport | Front faces | Scissor and readback rects | Blit |
|---|---|---|---|---|---|
| Offscreen render target | GL order: memory row 0 = bottom (NDC y = -1) | positive height, GL rect as is | clockwise in Vulkan space (GL's CCW, mirrored) | GL rect as is | to a target: rows as they are |
| Back buffer (swapchain) | top row first, as displayed | flipped (negative height) | counter-clockwise | converted from bottom-left | to the back buffer: rows mirrored |

So there is **exactly one flip, at presentation**. Shaders, UVs, light-space shadow math, `gl_FragCoord` (row + 0.5,
the same value as GL's lower-left origin) and bottom-left scissor rects all behave as in GL on every offscreen target,
with no shader change. Only a pass drawn straight into the back buffer has a top-left `gl_FragCoord`; nothing in the
engine relies on it there. Front faces are chosen per render pass (pipelines are already built per render pass).
`ClipSpace` in `GlslToVulkan.kt` keeps the depth remap; its flipped viewport and scissor equal the back-buffer case.

Pixel checks are now possible anywhere: `readPixels(target)` returns the target's memory as is, and
`readPixels(null)` reverses the back buffer's rows. Both return GL order, which equals OpenGL's readback.
`VulkanPresentGpuTest` asserts that the presented frame (geometry + post) is upright: sky at the top, floor at the
bottom.

## 2. Post-processing

`PostProcessPass` needed no change. It ping-pongs between two scratch targets (`PostChain`), then blits the result
back into the scene target. With the convention above, each effect samples its input upright.

**Found and fixed: SSAO read a dummy instead of the scene depth.** The sampler compatibility check
(`VkFrameResources.compatible`) only accepted a depth texture for a shadow (compare) sampler. SSAO reads the scene
depth through a plain `sampler2D`, which GL and Vulkan both allow when the texture's sampler does not compare, so it
got the black dummy and produced no occlusion. Now a plain sampler accepts a depth texture without compare.
`DescriptorCompatibilityTest` covers it. This was a one-function edit in a skate-render file, flagged for their
review.

## 3. Parity (`VulkanPostProcessParityGpuTest`, 1280x720, geometry + post)

| View | Effects | Mean | Within 2/255 | Max |
|---|---|---|---|---|
| main-default | bloom + FXAA (engine defaults) | 0.004 | 100.000% | 2 |
| main-ssao | SSAO (radius 0.01) | 0.077 | 99.291% | 15 |
| main-bloom | bloom (intensity 1, threshold 0.6) | 0.004 | 100.000% | 6 |
| main-tonemap | ACES (exposure 1.4) | 0.003 | 100.000% | 5 |
| main-gamma | gamma 2.2 | 0.003 | 100.000% | 5 |
| main-fxaa | FXAA | 0.004 | 100.000% | 2 |
| main-all | all five chained | 0.045 | 98.938% (100.000% within 8) | 7 |
| showcase-materials-{default,bloom,all} | as named; emissive drives bloom | ≤ 0.049 | ≥ 99.031% | ≤ 40 |
| showcase-overview-all | all five | 0.008 | 99.827% | 13 |

**Tolerances.**
- **Without SSAO:** as VK-03, mean ≤ 0.25 and ≥ 99.9% of pixels within 2/255.
- **With SSAO:** mean ≤ 0.25 and ≥ 99% within 16/255. SSAO compares raw depths with no bias, so a last-bit depth
  rounding difference flips single samples. That difference comes from GL's fixed-function depth range versus the
  Vulkan vertex-stage remap, and each flipped sample is worth intensity/8. The flips land on flat floors and along the
  floor's triangle diagonal. A broken depth read fails this bar: with the dummy bug, 7% of pixels were off by up to
  87/255.

The test also checks that every effect changes the image. Tonemap, gamma, bloom, FXAA and SSAO (at a small radius) all
do.

## 4. Notes and follow-ups

- **SSAO default radius (OpenGL too, skate-render):** `ssaoRadius` defaults to 1.5 and the shader uses it as a UV
  offset. Every sample then lands off screen and SSAO does nothing on either backend. The setting's doc says "in depth
  samples", so the shader probably wants `radius * texelSize`. Fixing it changes OpenGL output, so it is reported
  rather than changed.
- **Exact SSAO parity:** `VK_EXT_depth_clip_control` (negative-one-to-one) would let the hardware apply GL's depth
  range instead of the shader remap, likely making depth bit-identical. It would need a flag in `GlslToVulkan` (skate-render).
- **No per-draw allocation:** VkCommandList now caches the dummy vertex buffer list per pipeline and the fallback
  texture function; both were allocated on every draw (reported by skate-gameui). Two remain in skate-render files:
  `binding()` returns a `Pair` per vertex buffer, and `dummyFor` builds a `Pair` key.
- **Validation-sensitive spots:** the scene depth is sampled through a non-compare sampler in
  `DEPTH_STENCIL_READ_ONLY_OPTIMAL`, and blits run between passes on targets in their resting layouts.
